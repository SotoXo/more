## AUD-01 — regla de validación inexistente

**Causa raíz.** `prohibited_with` intentaba invocar `validateProhibitedWith`, inexistente en Laravel 13.1.1. El error producía 500 antes de llegar a Python tanto con upload como con imagen existente.

**Archivos y cambio.** `app/Http/Controllers/Superadmin/AiController.php:48`, `:75` y `:287`: las seis reglas pasan a `prohibits`, soportada por el framework instalado, junto con `required_without` recíproco. Las dos reglas de `existing_image_id` añaden existencia en `imagenes_prenda,id_imagen_prenda`. No se incorpora una extensión global del validator. Los demás límites, autorización y lectura de imágenes se conservan.

**Por qué.** El contrato admite exactamente una fuente no vacía. Ambas fuentes, ninguna, archivos inválidos o IDs inválidos se rechazan con 422 antes de inferencia; el ID inexistente no se difiere a un `findOrFail` con 404.

**Riesgo y límites.** Se conserva `findOrFail` después de la validación para una eliminación concurrente. Los tests comprueban el contrato con HTTP simulado; no prueban por sí solos disponibilidad del modelo ni todas las características de archivos reales.

**Tests y estado.** `tests/Feature/MatiAiP1Test.php:136`: 32 casos, analyze/barcode/label/similar × upload válido, existing válido, ambos, ninguno, archivo inválido, ID inexistente, negativo y textual. Los ocho casos válidos alcanzan la operación esperada con Bearer; los 24 inválidos no hacen HTTP ni crean runs. Un test adicional comprueba ambas/ninguna fuente de publicación. Pasan todos. Además, `controller-runtime-probe.json` ejecutó directamente controlador Laravel → HTTP FastAPI real → PostgreSQL real: **24/24** casos pasan (cuatro operaciones × upload/existing/ambas/ninguna/ID desconocido/archivo inválido). Las escrituras IA se hicieron en transacción y se revirtieron; no hubo escrituras comerciales. El probe excluye middleware, autenticación web y navegador. En el corte 20:32 Chrome A/E habían pasado mediante existing_image_id de imagen 13/producto 11. En el cierre posterior, Chrome autenticado completó A con archivo de la misma fotografía (image_id=null y SHA idéntico), B EAN-13, C QR y D OCR por archivo; E existing y F ya estaban acreditados.
